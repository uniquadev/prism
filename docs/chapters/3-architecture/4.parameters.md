# 3.4 PRISM Parameters

PRISM separates three kinds of configuration:

1. **Protocol constants** define the wire ABI and cannot change within Protocol
   1.0.
2. **Elaboration parameters** select synthesized capacity and compiled features.
3. **Runtime operation state** selects topology, formats, accumulator profile,
   policy, routes, windows, and retry behavior within compiled limits.

The project-wide defaults and derived functions live in
`repo/rtl/src/prism_pkg.sv`; modules refer to those values rather than repeating
literals. A module may expose a package value as a parameter default:

```systemverilog
parameter int unsigned DATA_W = prism_pkg::PRISM_AXIS_DATA_W;
```

Changing an elaboration parameter creates a new bitstream and therefore a new
capability response. Runtime values arrive through validated CONTROL setup and
do not require resynthesis.

## Protocol 1.0 constants

| Constant | Value | Consumer and reason |
|---|---:|---|
| `PRISM_VERSION_MAJOR`, `PRISM_VERSION_MINOR` | `1`, `0` | Header parser and host codec select Protocol 1.0. |
| `PRISM_ETHERTYPE` | `0x88B5` | Ethernet ownership classification. |
| `PRISM_ETH_MTU_BYTES` | `1500` | Maximum Ethernet payload used by Protocol 1.0. |
| `PRISM_CONTROL_WORD_BYTES` | `2` | Every PRISM packet class. |
| DATA, RES, CONTROL header bytes | `24` each | Exact packet validation and serialization. |
| PROGRESS header bytes | `40` | Exact feedback validation and serialization. |
| `PRISM_CHUNK_PAYLOAD_BYTES` | `1474` | Derived as `1500 - 2 - 24`; bounds DATA/RES numeric bytes. |

Changing any row is a protocol revision. Chunk geometry, First Element,
last-packet elements, `KEEP_W`, maximum packet beats, handle widths, and backend
lane counts are **derived values**, not independent public parameters.

## Platform and deployment capacity

All rows below are `ELABORATION_CAPACITY`: changing one requires a new bitstream.
The defaults describe the first intended profile, not measured capacity.

| Parameter | First-profile value | Concrete consumer | Legal rule and rationale |
|---|---:|---|---|
| `PRISM_AXIS_DATA_W` | `512` | OpenNIC adapters, packet streams, serializers | Positive multiple of 8; selected by the shell. |
| `PRISM_DATAPATH_CLK_HZ` | `322265625` | timers and constraints | Must equal the integrated packet clock. |
| `PRISM_CFG_CLK_HZ` | `125000000` | register CDC | Must equal the shell configuration clock. |
| `PRISM_NUM_PORTS` | `2` | ingress instances and egress columns | Positive; two independent full-duplex ports in the first profile. |
| `PRISM_NUM_INTERNAL_SOURCES` | `3` | logical egress source classes | Collective/result, management, and reliability classes; disabled classes may be compiled out. |
| `PRISM_MAX_FRAME_BYTES` | `1514` | admission and packet storage | Ethernet header plus the 1500-byte payload, excluding FCS. |
| `PRISM_MAX_LOCAL_CONTRIBUTORS` | `2` | contributor-binding table and trackers | `1..65535`; bounds runtime `expected_local_contributors`. |
| `PRISM_MAX_OPERATION_RESULT_ROUTE_RANGES` | `2` provisional | result-range table | Bounds disjoint runtime chunk ranges; one all-chunks range is the simple case. |
| `PRISM_MAX_REPLICATION_GROUPS` | `2` provisional | group replication table | Bounds installed destination sets; not a route-range count. |
| `PRISM_MAX_RESULT_DESTINATIONS_PER_GROUP` | `2` provisional | direct result-destination entries | Bounds egress/Result-Path/MAC next hops in one set. |

Node Role is runtime group state, not a global elaboration default. The first
profile installs `SINGLE`; another bitstream may advertise multiple roles, and
Protocol 1.0 retains `LEAF`, `INTERNAL`, and `ROOT`. At `LEAF`/`SINGLE`, local
contributors normally identify ranks; at `INTERNAL`/`ROOT`, they identify child
subtrees. They are never defined as physical ports.

## Compiled protocol and arithmetic support

These are `COMPILED_FEATURE` selections. Protocol registry membership does not
imply that a profile enables or implements a value.

| Selection | First target profile | Consumer |
|---|---|---|
| Collective semantics | `REDUCE`, `ALLREDUCE` | operation admission and collective unit |
| Reduction operator | `SUM` | arithmetic dispatch |
| Arithmetic tuple | `(FP32, FP32, CONTRIBUTOR_ORDERED, FP32, FP32)` | converters, accumulator backend, scheduler, packetizer |
| Node role | statically installed `SINGLE` group | management/static configuration and context validation |
| In-band control | disabled in first target; protocol retained | management unit and control serializer |
| Hop reliability / selective ACK / result ACK | disabled in first target; protocol retained | reliability unit, replay storage, timers |
| Leased sessions | disabled in first target | management ownership cleanup |
| Forwarding cut-through | disabled; closed packets only | VOQ eligibility and egress start authorization |

The advertised arithmetic capability is a five-field tuple, never the Cartesian
product of independent masks. Accumulator width is a backend property. The
512-bit FP32 profile derives 16 values per tile; ALU-array count remains an
architecture choice pending synthesis, not a protocol or user parameter.

## Concurrent operations and storage resources

These `ELABORATION_CAPACITY` values are provisional resource budgets. None is a
measured supported capacity until RTL elaboration and synthesis exist.

| Parameter | Initial target | State or storage bounded | Runtime value constrained |
|---|---:|---|---|
| `PRISM_OPERATION_CONTEXT_SLOTS` | `8` | prepared, active, complete, aborted, and releasing operation contexts, including retired-operation records | all non-free operation contexts |
| `PRISM_ACCUMULATOR_RANGE_SLOTS` | `16` | active and `OUTPUT_PENDING` element ranges | admitted window/work concurrency |
| `PRISM_MAX_DIRECT_STREAM_WINDOW_CHUNKS` | `8` | receive/duplicate window state | operation requested/admitted window |
| `PRISM_INGRESS_STAGING_BEATS` | `48` per port | non-backpressurable RX staging | none |
| `PRISM_PACKET_STORE_SLOTS_PER_PORT` | `8` | closed local-packet descriptors | concurrent local packets |
| `PRISM_PACKET_STORE_BEATS_PER_PORT` | `192` | local packet bytes | packet-store occupancy |
| `PRISM_VOQ_CAPACITY_BEATS` | `96` per logical source/egress queue | forwarding/injection backlog | queue availability |
| `PRISM_EGRESS_BUFFER_BEATS` | `4` per egress | TX elasticity | none |
| `PRISM_REPLAY_SLOTS` | `16` | retained direct transfers | requested replay slots when reliability is enabled |
| `PRISM_REPLAY_BUFFER_BEATS` | `384` | immutable replay packet bytes | replay occupancy |
| `PRISM_MGMT_REASSEMBLY_BYTES` | `8192` | one complete fragmented CONTROL transaction | accepted transaction size |

Logical VOQs must preserve per-source/per-egress packet behavior and concurrent
admission. The first implementation profile uses one physically separate FIFO
per source/egress pair. This favors simple independent read/write control over
balanced memory utilization; shared-cell packet memory remains a later
optimization requiring allocation, reclamation, and multi-request arbitration.

## Scheduling, forwarding, and reliability defaults

These values are `IMPLEMENTATION_PROFILE_DEFAULT`, not protocol semantics.

| Default | Initial value | Override/consumer |
|---|---|---|
| Forwarding policy | `PM_TRANSPARENT` | runtime node policy; forwarding unit |
| Scheduling policy | packet round robin with bounded mandatory service | compiled scheduler choice |
| Cut-through | off | compiled feature; only closed packet heads are eligible |
| Retry limit | `3` provisional | runtime operation policy, bounded by retry-state capacity |
| ACK timeout | `100 us` provisional | runtime operation policy and retry timer |
| Statistics counter width | `64` | compiled counter storage; no protocol effect |

Scheduling remains packet-granular through accepted `tlast`. A default may
populate static/reset configuration but cannot change the meaning of a Protocol
1.0 field.

## Runtime configuration and derived values

`RUNTIME_CONFIGURATION` includes local MACs, Node Role, Contributor bindings,
`expected_local_contributors`, parent action, result-range routes, replication
groups, result destinations, Result Path IDs, arithmetic tuple, Element Count,
window, and retry policy. Validation rejects a runtime value beyond its compiled
capacity or an arithmetic tuple absent from the compiled feature set.

`DERIVED_VALUE` includes `KEEP_W = DATA_W/8`, maximum frame beats, three
format-specific chunk geometries, First Element, payload length, accumulator
address width, table-handle width, and backend lane count. A derived value must
not also be independently configurable.

## Required elaboration checks

When those RTL files are implemented, elaboration must reject a non-byte AXI
width, fixed headers wider than the parser contract, queues smaller than one
promised packet, runtime-handle widths unable to address their capacities,
windows larger than tracker/replay state, or advertised tuples lacking a
converter, backend, finalizer, and packet path. Capability responses must be
generated from those checked constants; resource responses must report current
availability from the corresponding owners.
