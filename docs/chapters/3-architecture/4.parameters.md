# 3.4 PRISM Parameters

PRISM separates three kinds of configuration:

1. **Protocol constants** define the wire ABI and cannot change within Protocol
   1.0.
2. **Elaboration parameters** select synthesized capacity and compiled features.
3. **Runtime operation state** selects topology, formats, accumulator profile,
   policy, routes, windows, and retry behavior within compiled limits.

The project-wide defaults and derived functions live in
`repo/rtl/src/prism_pkg.sv`; modules refer to those values rather than repeating
literals. A module may expose a package value as a parameter default:

```systemverilog
parameter int unsigned DATA_W = prism_pkg::PRISM_AXIS_DATA_W;
```

Changing an elaboration parameter creates a new bitstream and therefore a new
capability response. Runtime values arrive through validated CONTROL setup and
do not require resynthesis.

## Protocol 1.0 constants

These names belong in `prism_pkg.sv` for one-source consistency, but editing
them is a protocol change rather than ordinary configuration.

| Constant | V1 value | Purpose |
|---|---:|---|
| `PRISM_VERSION_MAJOR`, `PRISM_VERSION_MINOR` | `1`, `0` | Wire-version negotiation. |
| `PRISM_ETHERTYPE` | `16'h88B5` | Experimental Layer-2 discriminator. |
| `PRISM_ETH_MTU_BYTES` | `1500` | Ethernet payload available to PRISM. |
| `PRISM_CONTROL_WORD_BYTES` | `2` | Version/opcode word. |
| `PRISM_DATA_HEADER_BYTES`, `PRISM_RESULT_HEADER_BYTES` | `24`, `24` | Fixed class headers after the control word. |
| `PRISM_CONTROL_HEADER_BYTES`, `PRISM_PROGRESS_HEADER_BYTES` | `24`, `40` | Fixed CONTROL and PROGRESS headers. |
| `PRISM_CHUNK_PAYLOAD_BYTES` | `1474` | Numeric bytes: `1500 - 2 - 24`. |

`elements_per_chunk(format)`, `chunk_count(Element Count, format)`, First
Element, last-packet elements, and backend lane counts are package **functions
or local parameters**, not public knobs. This prevents illegal combinations.

## Platform and deployment capacity

| Parameter | V1 default | Purpose |
|---|---:|---|
| `PRISM_AXIS_DATA_W` | `512` bits | OpenNIC packet datapath width. |
| `PRISM_DATAPATH_CLK_HZ` | `322_265_625` | Packet clock for two 100 Gbit/s ports. |
| `PRISM_CFG_CLK_HZ` | `125_000_000` | Shell configuration clock. |
| `PRISM_NUM_PORTS` | `2` | Independent full-duplex physical ports. |
| `PRISM_NUM_INTERNAL_SOURCES` | `3` | Collective/result, management, and reliability VOQ rows. |
| `PRISM_MAX_FRAME_BYTES` | `1514` | Ethernet frame without FCS. |
| `PRISM_NODE_ROLE_DEFAULT` | `SINGLE` | Two attached ranks, local aggregation, and local result delivery. |
| `PRISM_NUM_LOCAL_CONTRIBUTORS` | `2` | Default dense Contributor IDs; protocol width remains 16 bits. |
| `PRISM_MAX_RESULT_ROUTES` | `2` | Default two-rank ALLREDUCE fan-out. |

Local MACs, Contributor bindings, node role, parent action, result routes, and
Result Path IDs remain runtime state.

## Compiled protocol and arithmetic support

| Parameter | V1 default | Advertised effect |
|---|---:|---|
| `PRISM_COLLECTIVE_SEMANTIC_MASK` | REDUCE, ALLREDUCE | Both Protocol 1.0 semantics are executable. |
| `PRISM_REDUCTION_OPERATOR_MASK` | SUM | Element-wise sum backend operation. |
| `PRISM_INPUT_FORMAT_MASK` | FP16, BF16, FP32 | Endpoint DATA formats. |
| `PRISM_PARTIAL_FORMAT_MASK` | FP32 | Switch partial DATA format. |
| `PRISM_OUTPUT_FORMAT_MASK` | FP16, BF16, FP32 | RES formats. |
| `PRISM_ACCUM_PROFILE_MASK` | FP32 | Enabled accumulator representations. |
| `PRISM_ACCUM_POLICY_MASK` | EAGER, CONTRIBUTOR_ORDERED | Streamed arrival-order or deterministic local fold order. |
| `PRISM_ENABLE_INBAND_CONTROL` | `1` | Protocol 1.0 setup, discovery, resources, status, and lifecycle. |
| `PRISM_ENABLE_HOP_RELIABILITY` | `1` | PROGRESS, duplicate handling, ACK, replay, and retry. |
| `PRISM_ENABLE_SELECTIVE_ACK`, `PRISM_ENABLE_RESULT_ACK` | `1`, `1` | Window bitmap and independent result-path completion. |
| `PRISM_ENABLE_LEASED_SESSIONS` | `1` | Ownership expiry and cleanup. |
| `PRISM_SECURITY_PROFILE_MASK` | `LAB_UNAUTHENTICATED` | Initial lab management profile. |

The supported arithmetic capability is generated as five-field tuples:
`(input, accumulator profile, accumulation policy, partial, output)`. Masks are
only registry filters; the implementation advertises a tuple only when all
required converters, backend, finalizer, and wire paths are present.

Accumulator width is a backend property. A future Kulisch profile adds typed
state, conversion, and capability entries without widening shared commit types.

For the V1 512-bit datapath, geometry derives to 16 FP32 values per normalized
tile. FP16/BF16 input can generate two such tiles per port per cycle. The
default FP32 backend therefore contains four 16-lane ALU arrays (64 scalar
ALUs). These values are derived, not configurable parameters.

## Concurrent operations and storage resources

| Parameter | V1 default | Purpose |
|---|---:|---|
| `PRISM_OPERATION_CONTEXT_SLOTS` | `8` | Prepared, active, complete, or releasing contexts not yet freed. |
| `PRISM_MAX_ACTIVE_OPERATIONS` | `8` | Collective operations allowed to make progress concurrently. |
| `PRISM_ACCUMULATOR_RANGE_SLOTS` | `16` | Active or `OUTPUT_PENDING` global element ranges shared by all operations. |
| `PRISM_OPERATION_WINDOW_CHUNKS` | `8` per direct stream | Maximum admitted receive window. |
| `PRISM_INGRESS_STAGING_BEATS` | `48` per port | Two maximum frames at the non-backpressurable RX boundary. |
| `PRISM_PACKET_STORE_SLOTS_PER_PORT` | `8` | Closed local packets retained per ingress. |
| `PRISM_PACKET_STORE_BEATS_PER_PORT` | `192` | Full-frame backing storage for those slots. |
| `PRISM_VOQ_DEPTH_BEATS` | `96` per source/egress cell | Four maximum packets in every row-parallel VOQ cell. |
| `PRISM_EGRESS_BUFFER_BEATS` | `4` per port | Final elastic TX stability stage. |
| `PRISM_REPLAY_SLOTS` | `16` | Direct reliable transfers awaiting ACK. |
| `PRISM_REPLAY_BUFFER_BEATS` | `384` | Full-frame capacity for all default replay slots. |
| `PRISM_MGMT_REASSEMBLY_BYTES` | `8192` | Maximum atomic fragmented CONTROL transaction. |

Eight active operations share sixteen live ranges and the arithmetic backends.
These initial limits must be revalidated after OpenNIC synthesis; discovery
reports both compiled maxima and current availability.

The VOQ matrix is physically or logically write-parallel by source row. All two
ingress rows and internal injection rows may enqueue in one cycle, even toward
the same egress, because they target distinct `VOQ[source][egress]` cells.

## Scheduling, forwarding, and reliability defaults

| Parameter | V1 default | Purpose |
|---|---:|---|
| `PRISM_FORWARD_POLICY_DEFAULT` | `PM_TRANSPARENT` | Forward non-local traffic; strict ownership remains runtime-selectable. |
| `PRISM_SCHED_POLICY` | `SCHED_RR_AGE` | Packet round robin with age escalation for mandatory traffic. |
| `PRISM_SCHED_MANDATORY_MAX_WAIT_PKTS` | `8` | Eligible packet starts allowed ahead of a waiting result/ACK/control packet. |
| `PRISM_CUT_THROUGH_ENABLE` | `0` | Initial build starts closed packets to simplify gap-free proof. |
| `PRISM_RETRY_LIMIT_DEFAULT` | `3` | Direct-transfer retry limit unless overridden. |
| `PRISM_ACK_TIMEOUT_US_DEFAULT` | `100` µs | Direct peer ACK deadline. |
| `PRISM_SELECTIVE_ACK_WINDOW` | `8` chunks | Default direct-stream bitmap/window. |
| `PRISM_MGMT_MAX_FRAGMENTS` | `8` | Maximum CONTROL fragments per atomic transaction. |
| `PRISM_STATS_COUNTER_W` | `64` bits | Saturating counters. |

Scheduling is packet-granular and cannot preempt an accepted packet before
`tlast`. Retry/window values may be overridden per operation within compiled
limits.

## Required elaboration checks

`prism_pkg.sv` and `prism_switch_top` must reject builds with a non-byte AXI
width, fixed headers wider than the first-beat parser, insufficient route-mask
bits, queues smaller than one promised packet, unsupported advertised tuples,
windows larger than tracker/replay capacity, non-power-of-two bank selections,
or missing packetizer/finalizer support for an enabled output format. Capability
and resource responses are generated from the same checked constants.
